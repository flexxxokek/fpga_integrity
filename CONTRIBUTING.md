# Правила работы команды

## Ветки и ревью

- `main` — стабильная ветка, только через PR.
- Рабочие ветки: `feat/<тема>`, `fix/<тема>`, `docs/<тема>`.
- Каждый PR ревьюит минимум один другой участник команды.
- PR должен проходить CI (lint + регрессия) до слияния.

## Стиль RTL (SystemVerilog)

- Имена: `lower_snake_case`; параметры: `UPPER_SNAKE_CASE`.
- Синхронный сброс, активный высокий; без latch-ей; без вендорных примитивов
  в `rtl/cores`, `rtl/wrappers`, `rtl/harness`.
- `verilator --lint-only -Wall` — без замечаний.
- Комментарии и идентификаторы — на английском; документация — на русском.
- Сгенерированные файлы (CRC-уравнения) помечаются шапкой `// Generated by ...`
  и не правятся вручную.

## Стиль Python (tb/, scripts/)

- PEP8, форматтер black; типизация приветствуется.
- Эталонные модели — только в `tb/model.py`, не дублировать в тестах.
- Каждый тест самодостаточен и детерминирован (seed фиксируется).

## Коммиты

- Осмысленные сообщения с префиксом области: `rtl:`, `tb:`, `harness:`,
  `scripts:`, `docs:`, `boards:`.
- Один коммит — одно логическое изменение.

## Документация

- Изменение интерфейсов/параметров → обновить `docs/spec.md` в том же PR.
- Новое архитектурное решение → запись в `docs/decisions.md`.
- Получение платы → заполнить `docs/board.md` отдельным PR.

## Треки ответственности

Рекомендуемое разделение (закрепляется командой):
RTL-ядра · верификация · стенд и хост-скрипты · анализ и документация.
