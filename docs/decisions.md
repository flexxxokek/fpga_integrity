# Журнал решений

| ID | Решение | Обоснование | Статус |
|----|---------|-------------|--------|
| D-01 | RTL на SystemVerilog | задано условиями проекта | принято |
| D-02 | Testbench на cocotb (Python) | задано условиями; быстрые эталонные модели | принято |
| D-03 | Симулятор Verilator ≥ 5.0 | самый быстрый RTL-симулятор, поддержка cocotb | принято |
| D-04 | Единый интерфейс обёрток AXI4-Stream + sideband | сопоставимость алгоритмов и переиспользование TB/стенда | принято |
| D-05 | Board-независимый RTL; board-слой в `boards/` | модель платы неизвестна до получения | принято |
| D-06 | Объём: parity, checksum, Fletcher, Adler, CRC-8/16/32/32C; SHA-256 — расширенный трек; MD5/SHA-1/SHA-3 исключены | покрыть все классы; MD5/SHA-1 устарели, SHA-3 — отдельная большая работа | принято, может быть пересмотрено |
| D-07 | RX: «пересчитать и сравнить», пакет пропускается + `tag_error` | единообразие всех алгоритмов, сопоставимая латентность | принято |
| D-08 | Тег: целые байты, little-endian, отдельные beat-ы после payload | простое единообразное правило для всех TAG_WIDTH | принято |
| D-09 | Статические метрики — из отдельных OOC-сборок каждого ядра | стенд не должен искажать сравнение ресурсов | принято |
| D-10 | Обмен с хостом: текстовый протокол поверх UART | board-независимость, простота отладки | принято, параметры после платы |
| D-11 | Кристалл EP4CE115F29C7 (DE2-115), САПР Quartus Prime Lite 21.1, частота стенда 12.5 МГц = CLOCK_50/4, UART 115200 | плата получена 2026-11-23; Fmax полного стенда ≈ 23.6 МГц, поэтому 50 МГц не закрывает тайминг | принято |
| D-12 | Инжектор ошибок стоит после TX и искажает только payload-beat-ы | тег должен считаться по чистым данным; иначе RX сверяет тег с уже искажённым payload и ошибка не обнаруживается |
| D-13 | Broadcast через регистр с маской принявших lanes | lane не может принять один и тот же beat дважды, пока другой lane не готов; поток идентичен для всех алгоритмов |
| D-14 | SHA-256 сериализуется little-endian, digest byte 0 в младшем байте тега | единое правило с остальными алгоритмами (D-08) |
| D-15 | `report_uart` выдаёт упрощённый текстовый отчёт `RESULT,<lane>,...` + `DONE` | достаточно для симуляции и bring-up; полный протокол из measurement_plan — после платы |
