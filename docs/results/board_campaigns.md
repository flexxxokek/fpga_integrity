# Кампании на DE2-115: sim ↔ board

Прогоны выполнены 2026-11-25 через JTAG (USB-Blaster) и `/dev/ttyUSB0`
(115200 8N1). Для каждого режима `MODE` — константа времени компиляции, поэтому
прошивка пересобиралась отдельно, загружалась в EP4CE115F29 и выдавала отчёт
`RESULT,…` + `DONE` сразу после конфигурации (POR → кампания → UART).

Симуляционные референсы сгенерированы с теми же параметрами, что и прошивка:
`DATA_WIDTH=32`, `NUM_PACKETS=64`, `LEN_MIN=LEN_MAX=64`, `SEED=0x12345678`,
GE-параметры по умолчанию. Сырые логи: `data/board_*_2026-11-25.log`,
референсы: `data/sim_mode*_w32.csv`, `data/sim_clean_w32.csv`.

## 1. Сравнение счётчиков

Для каждой строки сверены **все** поля шести `RESULT` (packets, corrupted,
detected, missed, false, bytes, cycles, weight-бакеты). «sim/board» — значение
из симуляции / с платы.

| MODE | Кампания | corrupted sim/board | missed sim/board | false sim/board | cycles parity sim/board | cycles SHA sim/board | Результат |
|---:|---|---:|---:|---:|---:|---:|---|
| 0 | clean | 0/0 | 0/0 | 0/0 | 1344/1344 | 10304/10304 | OK |
| 1 | single-bit | 384/384 | 0/0 | 0/0 | 1344/1344 | 10304/10304 | OK |
| 2 | burst | 384/384 | 64/64 | 0/0 | 1344/1344 | 10304/10304 | OK |
| 3 | byte-swap | 384/384 | 64/64 | 0/0 | 1344/1344 | 10304/10304 | OK |
| 4 | zero-insert | 384/384 | 36/36 | 0/0 | 1344/1344 | 10304/10304 | OK |
| 5 | Gilbert–Elliott | 18/18 | 1/1 | 0/0 | 1344/1344 | 10304/10304 | OK |
| 6 | zero all | 384/384 | 0/0 | 0/0 | 1344/1344 | 10304/10304 | OK |
| 7 | invert all | 384/384 | 64/64 | 0/0 | 1344/1344 | 10304/10304 | OK |
| 8 | randomize all | 384/384 | 64/64 | 0/0 | 1344/1344 | 10304/10304 | OK |
| 9 | tag corruption | 384/384 | 0/0 | 0/0 | 1344/1344 | 10304/10304 | OK |

Итого: **10/10 кампаний, 60/60 lane-отчётов совпали с симуляцией полностью**,
включая счётчики тактов и весовые бакеты.

## 2. Тайминг каждой сборки

Fmax и slack получены из TimeQuest (slow 1200 mV 85C) той же сборки, которой
была залита плата. Целевая частота стенда — 12.5 МГц.

| MODE | Fmax, МГц | Worst setup slack, нс | Timing @ 12.5 МГц |
|---:|---:|---:|---|
| 0 (clean, финальная прошивка) | 20.45 | +10.939 | met |
| 1 | 14.32 | +10.183 | met |
| 2 | 15.71 | +10.547 | met |
| 3 | 18.94 | +10.261 | met |
| 4 | 19.35 | +10.857 | met |
| 5 | 18.13 | +10.544 | met |
| 6 | 19.95 | +10.689 | met |
| 7 | 19.70 | +10.659 | met |
| 8 | 19.20 | +9.677 | met |
| 9 | 14.80 | +10.280 | met |

Изначально сборки режимов 1–4 и 9 имели Fmax 5.5–7.2 МГц и **не закрывали**
тайминг: в инжекторе выбирался бит через `rng_q % valid_bits`, и Quartus
синтезировал широкий делитель. Поскольку `valid_bits` всегда одна из степеней
двойки (8/16/32/64), деление заменено на эквивалентную битовую маску
`rng_q & (valid_bits - 1)`; после этого все режимы проходят тайминг.
Режимы 6–8 mask не используют и остались на уровне ~19–20 МГц; MODE=5
идёт по отдельному GE-тракту (18.13 МГц).

## 3. Важные оговорки

- Заголовочное значение Fmax 20.45 МГц в [board.md](board.md) относится к
  clean-прошивке. Остальные сборки имеют Fmax 14.32–19.95 МГц, но все проходят
  static timing на 12.5 МГц с положительным slack'ом.
- При подготовке прогона обнаружилось, что MODE=5 вообще не синтезировался в
  Quartus из-за неинициализированных `ge_rng` / `ge_state` в `always_comb`
  (Verilator это не считал ошибкой). Исправлено добавлением безусловных
  присваиваний в начале блока; симуляционные RESULTS после правки побайтово
  совпали с прежними.
- Полная регрессия и покрытие после правки RTL пересчитаны заново —
  [test_report.md](../test_report.md), [coverage.md](../coverage.md).
