# Итоговое сравнение и выводы

Все числа ниже перегенерированы из кода текущего коммита (`make sim-measure-all`,
`make sim-false-rate`, `make synth`). Первичные данные: `data/*.csv` и
`syn/reports/*.rpt` (генерируются `make synth`). Верификация: 249/249 тестов
в 94 конфигурациях, покрытие RTL 95.45 % ([docs/coverage.md](../coverage.md)).

## 1. Аппаратные затраты

Метрика — **gate-equivalent cells** после `synth -noabc` в Yosys (прокси для
LUT) и число триггеров. Это не LUT/FF вендорной САПР: Fmax и реальные LUT
появятся только после synthesis/P&R под конкретную плату.

| Алгоритм | gates @ w32 | FF @ w32 |
|---|---:|---:|
| parity_even | 134 | 4 |
| crc8 | 390 | 18 |
| crc16 (ARC / CCITT) | 454 | 34 |
| crc32 | 2002 | 66 |
| crc32c | 2382 | 66 |
| checksum16 | 2576 | 76 |
| fletcher32 | 10762 | 106 |
| fletcher16 | 13076 | 58 |
| sha256 | 35872 | 6884 |
| adler32 | 45796 | 66 |

Наблюдения:

- CRC дешевле checksum и Fletcher при сравнимом или лучшем обнаружении ошибок.
- Adler-32 дорог из-за двух делителей по модулю 65521 на каждый байт.
- SHA-256 на два порядка дороже по триггерам и на порядок по комбинационной
  логике; это отдельный трек, а не замена CRC.

## 2. Производительность в симуляции

На `DATA_WIDTH=32` все пять «лёгких» алгоритмов отдают **одинаковое** число
тактов (845 на 2013 байт, ≈0.42 такта/байт). SHA-256 — 6050 тактов
(≈3.0 такта/байт). Причина: все лёгкие ядра потребляют одно слово за такт и
имеют комбинационную финализацию, поэтому разница в алгоритме не влияет на
пропускную способность этой архитектуры. Сравнивать алгоритмы по тактам без
Fmax бессмысленно; требуется критический путь из вендорного синтеза.

## 3. Способность обнаруживать ошибки

Доля **необнаруженных** искажений (undetected rate; меньше — лучше):

| Кампания | parity | checksum16 | fletcher16 | adler32 | crc32 | sha256 |
|---|---:|---:|---:|---:|---:|---:|
| Gilbert–Elliott (RTL, 256 пак.) | 45.6% | 0% | 0% | 0% | 0% | 0% |
| HD sweep, m=1…3, n=64…2048 | ~33% | ~1% | ≈0% | ≈0% | 0% | 0% |
| Koopman HDLen (8 векторов) | 87.5% | 0% | 0% | 0% | 37.5% | 0% |

Важные оговорки:

- «0%» для 90 искажённых пакетов означает лишь верхнюю границу 95% ДИ ≈4.1%,
  а не доказанную нулевую вероятность. Для надёжного ранжирования нужны
  10³–10⁶ событий (методика Koopman/Maxino).
- 8 адверсариальных векторов — проверка свойств, а не статистика.
- Повреждение тега (`MODE=9`) обнаруживается всеми методами в 256/256 случаях.

## 4. Практический вывод

Если нужна минимальная площадь при гарантированном обнаружении burst-ошибок
длиной ≤ 32 бит — CRC-32 (2002 ячейки, 66 FF) лучше checksum16 по обнаруживающей
способности и сопоставим по площади. Parity пригоден только как дешёвая
предварительная проверка. Adler-32 и Fletcher проигрывают CRC по площади и не
дают выигрыша в обнаружении на этих кампаниях. SHA-256 оправдан только когда
требуется криптографическая стойкость, а не просто контроль целостности.

Окончательные рекомендации по применимости могут быть даны после этапа 3–4,
когда появятся Fmax, реальные LUT/FF и результаты на плате.
