# Техническая спецификация

## 1. Назначение и объём

Набор синтезируемых RTL-модулей контроля целостности потоковых данных
с единым интерфейсом, пригодных для:
- независимой верификации;
- совместного использования в измерительном стенде на FPGA;
- корректного сравнения аппаратных затрат и производительности.

## 2. Общие требования к RTL

| Требование | Значение |
|------------|----------|
| Язык | SystemVerilog, синтезируемое подмножество |
| Вендорные примитивы / IP | запрещены в `rtl/cores`, `rtl/wrappers`, `rtl/harness` |
| Тактирование | один тактовый домен `clk` |
| Сброс | синхронный, активный высокий (`rst`) |
| Ширина шины | параметр `DATA_WIDTH ∈ {8, 32, 64}` |
| Пропускная способность | 1 слово/такт без «пузырей» (кроме финализации тега, см. п. 5) |
| Длина пакета | 0…`MAX_PACKET_LEN` байт (по умолчанию 4096) |
| Паузы / backpressure | корректная работа при `tvalid=0` и `tready=0` в любой момент |
| `tkeep` | на `tlast` — непрерывные младшие байты; на остальных словах — все единицы |

Ограничение `MAX_PACKET_LEN` введено для корректного накопления в Fletcher/Adler
без переполнения аккумуляторов; стратегия редукции по модулю описывается
в комментариях к соответствующим ядрам.

## 3. Единый интерфейс обёрток

### Потоковый интерфейс (AXI4-Stream)

| Сигнал | Направление | Ширина | Назначение |
|--------|-------------|--------|------------|
| `s_axis_tdata` / `m_axis_tdata` | in / out | `DATA_WIDTH` | данные, байт 0 = `tdata[7:0]` |
| `s_axis_tkeep` / `m_axis_tkeep` | in / out | `DATA_WIDTH/8` | валидные байты |
| `s_axis_tvalid` / `m_axis_tvalid` | in / out | 1 | валидность |
| `s_axis_tready` / `m_axis_tready` | out / in | 1 | готовность |
| `s_axis_tlast` / `m_axis_tlast` | in / out | 1 | конец пакета |

### Служебные сигналы

| Сигнал | Направление | Назначение |
|--------|-------------|------------|
| `tag_value` | out | вычисленный тег целостности (для отладки и измерений) |
| `tag_valid` | out | строб готовности тега (совпадает с `tlast` выходного пакета) |
| `tag_error` | out (RX) | 1 — тег не совпал; строб на выходном `tlast` |
| `busy` | out | ядро финализирует тег, новые пакеты не принимаются (`tready=0`) |

## 4. Правила передачи тега

- `TAG_WIDTH` — ширина тега алгоритма; `TAG_BYTES = ceil(TAG_WIDTH / 8)`.
- Тег передаётся целыми байтами, little-endian, неиспользуемые старшие биты = 0.
- Генератор (TX) добавляет тег отдельными beat-ами после `tlast` payload.
- Проверяющий модуль (RX) буферизует хвост потока (глубина зависит от `TAG_BYTES`
  и `DATA_WIDTH`), извлекает тег, пересчитывает его по payload и сравнивает.
- При несовпадении RX поднимает `tag_error`, но пакет пропускает дальше
  (решение об отбрасывании — за вышестоящим уровнем).
- Стратегия «пересчитать и сравнить» едина для всех алгоритмов (включая CRC),
  чтобы латентность и поведение были сопоставимы.

## 5. Латентность и busy

- Для parity/checksum/Fletcher/Adler/CRC тег готов в течение 1 такта после
  последнего слова payload; `busy` не используется. Сигнал `tag_valid` на TX
  появляется после финализации и передачи всех байтов тега, то есть примерно
  через `4 + ceil(ceil(TAG_WIDTH/8) / (DATA_WIDTH/8))` тактов; тест
  `test_wrapper.latency` проверяет эту оценку для каждой ширины.
- Для SHA-256 финализация (padding + последние раунды) занимает несколько тактов;
  на это время `s_axis_tready=0`, `busy=1`.
- Точная латентность каждого ядра фиксируется в `tb/` и проверяется тестами;
  она является одной из сравниваемых метрик.

## 6. Параметры алгоритмов

### CRC (один параметризуемый движок)

| Вариант | Полином | Init | RefIn/RefOut | XorOut | Check (`"123456789"`) |
|---------|---------|------|--------------|--------|------------------------|
| CRC-8/SMBUS | 0x07 | 0x00 | false/false | 0x00 | 0xF4 |
| CRC-16/CCITT-FALSE | 0x1021 | 0xFFFF | false/false | 0x0000 | 0x29B1 |
| CRC-16/ARC | 0x8005 | 0x0000 | true/true | 0x0000 | 0xBB3D |
| CRC-32/ISO-HDLC | 0x04C11DB7 | 0xFFFFFFFF | true/true | 0xFFFFFFFF | 0xCBF43926 |
| CRC-32C | 0x1EDC6F41 | 0xFFFFFFFF | true/true | 0xFFFFFFFF | 0xE3069283 |

### Остальные

| Алгоритм | Параметры | Эталон |
|----------|-----------|--------|
| Parity | even / odd | собственная модель |
| Checksum | ширина 8/16/32; режим wrap / one's complement (RFC 1071) | собственная модель |
| Fletcher-16 / 32 | размер блока 8 / 16 бит | собственная модель |
| Adler-32 | modulo 65521 (RFC 1950) | `zlib.adler32` |
| SHA-256 | FIPS 180-4 | `hashlib.sha256` |

Известные векторы: Adler-32(`"123456789"`) = `0x091E01DE`;
SHA-256(`"abc"`) = `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`.
Остальные векторы генерируются эталонными моделями и фиксируются в `tb/vectors/`.

## 7. Исключения из объёма

MD5 и SHA-1 исключены как криптографически устаревшие и не дающие пользы
для сравнения методов контроля целостности. SHA-3 исключён как существенно
иная конструкция (sponge), требующая отдельной большой работы.
Решение зафиксировано в [decisions.md](decisions.md) (D-06) и может быть пересмотрено командой.
